# Risk Register — Human & Cooperative Workflow Runtime release

**Companion to `release-plan.md`. Severity = likelihood × impact on the
master DoD. Every risk names its owning phase from `file-change-map.md`.**

| ID | Risk | L | I | Mitigation | Owner phase |
|----|------|---|---|------------|-------------|
| R1 | **Migration / signature canonicalization.** Graph signatures and `graph_hash` pins are computed over `model_dump(mode="json")` (`src/kernel/kernel.py:graph_fingerprint`); `BundleManifest` signatures likewise. Adding ANY field to `GraphSpec` or `BundleManifest` silently invalidates every existing `.sig` sidecar, breaks hash-pinned resume of in-flight graph runs, and breaks `.fkz` verification. | Med | **High** | Freeze `GraphSpec`/`BundleManifest` for this release (the new layer doesn't need to touch them). If a change ever lands, version the canonicalization (ADR-002 §"signing interaction") and re-sign examples in the same commit. Contract tests assert fingerprint stability against golden hashes. | contracts |
| R2 | **Cross-language drift.** Master handoff assumes mixed Python/TS; repo is Python-only. If TS is introduced later against hand-written types, contracts fork. | Low (now) | High (later) | ADR-001: Pydantic canonical; ship `fukasawa schema dump` (JSON Schema export) in this release so any future TS consumer generates types, never hand-writes them. DoD §2.2 cross-language fixtures deferred until a TS consumer exists (Gate A amendment — see R8). | contracts |
| R3 | **UI duplication.** Desktop grows a second validator or inline business rules (explicitly forbidden by master handoff §16). Precedent risk: GUI currently has only 2 thin tabs; 15 new §16 requirements is a big surface. | Med | Med | All new desktop behavior lands as typed functions in `src/gui/services.py` first (ADR-007); `tests/test_gui_workflow.py` asserts views call services (integration test §15.6 "no duplicated business logic in UI"); code review gate on any `import` in `src/gui/` that isn't `services`/`workflow_views`. | desktop |
| R4 | **Packaging.** PyInstaller must bundle new example/fixture data files and any new hidden imports; `packaging/fukasawa.spec` + `rthook_tk.py` are hand-tuned; 3-OS CI builds (`.github/workflows/build.yml`) only run on tag/main. | Med | Med | Phase 9 runs `./packaging/build.sh` on Linux and smoke-tests `dist/fukasawa workflow validate <pilot>`; spec file updated in the packaging phase ONLY (single owner); §2.3 permits explicit deferral with documented blocker for the other OSes. | packaging |
| R5 | **Persistence.** New ledger tables must not disturb existing DBs (`fukasawa.db` in the wild, append-only doctrine); interrupted writes mid-promotion could strand a workflow between states; old-version drafts must load after schema bumps. | Med | High | Additive-only DDL in `RunLedger._ensure_schema` (existing idiom); promotion writes artifact-then-state in one transaction; `schema_version` on every new row + loader shims (ADR-002); §15.4 tests: interrupted-write recovery, old-version load. | promotion |

| R7 | **Scope creep.** §5 objects invite modeling ambition (org charts, roles, marketplaces — all §4 non-goals). 16 rules can balloon into a rules DSL. | Med | Med | Rules are plain Python functions in one registry module, not a DSL; every proposed field beyond §5 minimums goes to `tasks/backlog.md` instead of the schema (§21); phase completion notes list rejected expansions. | all |
| R8 | **DoD internally unsatisfiable as written.** §2.2 requires "cross-language fixtures prove Python and TypeScript agree" but the repo has no TypeScript and the operator confirmed Python-only for now. Unresolvable without either amending the DoD or adding a TS package. | **Certain** | Med | Escalated as THE Gate A decision for Opus/operator: recommend amending §2.2 to "when a TS consumer exists, it must be generated from the exported JSON Schema and verified by fixture tests." | R9 | **Validator false positives.** 16 deterministic rules against messy observed workflows (unwritten rules, ambiguous terms — rule 13/14 are inherently heuristic) may flag noise, eroding trust in findings. | Med | Med | Gate C includes explicit false-positive review on the pilot + adversarial fixtures (Grok Build task §11.4); rules 13/14 default severity `non-blocking`; every rule's detection logic documented in the rule catalog so a human can predict it. | validator |
| R10 | **Concurrent-edit conflicts.** Multiple agents (Codex/Grok/Antigravity/Jules) touching shared files (`cli.py`, `ledger.py`, `services.py`) simultaneously. | Med | Med | `file-change-map.md` gives every file exactly one owning phase; shared files are edited in exactly one phase each; §13 "only one branch owns a file group at a time"; Jules files defect reports instead of editing production code (§11.7). | all |
| R11 | **Trust-store / secrets hygiene.** New workflow artifacts may tempt embedding of real names, hosts, or paths (the repo already had one LAN-IP leak, fixed in `9d49d56`). Pilot uses a real publication workflow. | Low | High | Pilot fixtures use placeholder hosts/paths per `config/model_endpoints.example.yaml` convention; the pending cross-repo gitleaks task (HANDOFF.md item 1) becomes more urgent — recommend landing the gitleaks Action on this repo within the contracts phase. | hardening |
